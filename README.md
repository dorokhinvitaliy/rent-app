# Место — локальная подборка квартир

Веб-приложение для долгосрочной аренды: NestJS + React + Vite + TypeScript, локальная SQLite и браузерный сбор через Playwright. Интерфейс на русском, адаптирован для телефона и компьютера.

## Запуск

Требуется **Node.js 24+** и npm. Для браузерного сбора нужна графическая сессия на компьютере, где работает API.

```sh
npm install
npm run browser:install
npm run dev
```

Открыть **http://127.0.0.1:5173**. API: http://127.0.0.1:3001/api.

Первая база пустая. Кнопка «Посмотреть на примере» добавляет шесть явно помеченных демонстрационных квартир. Все их цены и адреса вымышлены, фотографии интерьеров — иллюстрации Unsplash. Демо можно убрать одной кнопкой, не удаляя свои объявления.

Сборка и запуск без Vite:

```sh
npm run build
npm start
```

Готовый интерфейс и API доступны по **http://127.0.0.1:3001**. Не требуется Docker или отдельный сервер баз данных. `node:sqlite` в Node 24.1 выводит стандартное предупреждение об экспериментальном API.

## Что реализовано

- Импорт Циана через фоновый Chromium: отдельная квартира или до 3 страниц каталога, до 30 объектов за запуск, пауза между переходами, ручная капча, сохранение сессии.
- Экспериментальный адаптер Яндекс Недвижимости на DOM/JSON-LD; не подтвержден на живых объявлениях.
- Импорт сохраненного HTML (до 8 МБ), ручное добавление, редактирование и удаление квартир.
- Фотографии и галерея, поиск по тексту, источнику, комнатам, бюджету аренды и въезда, варианты без комиссии, сортировка.
- Избранное, личные заметки, сравнение до четырех квартир.
- Оценка 1 плавно отправляет объявление в архив; повторный импорт сохраняет оценку. В архиве можно вернуть вариант в подборку (сбросить оценку) или поставить 2–5.
- Расчет месячных расходов, суммы на въезд, расходов за срок и средней стоимости месяца.
- XLSX для текущей отфильтрованной подборки или сравнения: числовые ячейки, формулы, сохраненные результаты формул, автофильтр, ссылки на источник и первое фото, пояснения на отдельном листе.
- SQLite: объявления, заметки, избранное, история последних 30 запусков. При перезапуске незавершенные задания помечаются прерванными.
- Повторный импорт одного URL обновляет запись. Параметры отслеживания у ссылок на квартиры удаляются. Избранное, заметки и введенные пользователем прочие расходы сохраняются; неизвестные при обновлении суммы не стирают старые значения.

## Поиск по параметрам

Главный сценарий — форма **«Каким будет ваш следующий дом?»** на главной странице. Выберите город (Москва, Санкт-Петербург или Казань), комнаты, бюджет, площадь и максимальное время **пешком** до метро. В дополнительных параметрах — минимальный этаж, отсутствие комиссии, лимит результатов и число страниц. Нажмите **«Найти квартиры»**: приложение само формирует URL Циана и запускает Playwright. Ссылка на выдачу доступна рядом для проверки параметров на площадке.

Параметры последнего запуска сохраняются в браузере. Прогресс и ручная капча отображаются прямо под формой. Вся подборка остается видимой; результаты отдельного запуска доступны по кнопке «Показать только результаты запуска». Импорт по ссылке остается дополнительным способом.

После разбора карточки сервер повторно проверяет цену, площадь, комнаты, этаж, время до метро и комиссию. Неизвестное значение при заданном ограничении **не считается совпадением**: объявление пропускается с пояснением. Время на машине не принимается за время пешком. Фильтр «Без комиссии» проверяется локально; он не эквивалентен «от собственника». Из-за ограниченного числа страниц подходящих квартир может оказаться меньше заданного лимита.

`POST /api/search/cian` принимает JSON, например:

```json
{
  "region": "1",
  "rooms": [1, 2],
  "minRent": 50000,
  "maxRent": 90000,
  "minArea": 40,
  "maxArea": 70,
  "metroMinutes": 10,
  "minFloor": 2,
  "noCommission": false,
  "limit": 10,
  "pages": 3
}
```

Числа здесь — пример критериев поиска, не цены найденных объектов. `null` для числовых ограничений означает отсутствие ограничения; пустой список комнат — любые комнаты. Справочник городов пока ограничен тремя вариантами, произвольные станции метро не выбираются. Проверка URL, полей, фильтрации и всего конвейера сделана на тестовых данных; полный поиск по этим параметрам на живой выдаче пока не подтвержден.

## Как собирать Циан

1. Найдите нужный каталог **долгосрочной** аренды в обычном браузере и скопируйте URL. Пример: `https://www.cian.ru/cat.php?deal_type=rent&engine_version=2&offer_type=flat&region=1&type=4`. Также поддерживаются ссылки вида `https://www.cian.ru/rent/flat/123456789/` (пример формата, не действительное объявление).
2. Нажмите «Добавить квартиру» → «В браузере», вставьте ссылку, выберите лимит и число страниц.
3. Chromium запустится в фоне. Если потребуется капча, нажмите «Открыть окно проверки» и пройдите ее **вручную**. На запрос открытия и проверку отводится по три минуты.
4. Смотрите статус в «Источники и импорт». Можно отменить сбор. Уже сохраненные квартиры остаются в базе даже при ошибке следующей страницы.
5. Откройте квартиру и уточните комиссию, залог, коммунальные и счетчики. Неизвестные платежи помечены отдельно, итог указан «от».

Если браузер не запускается: `npm run browser:install`. Не запускайте второй экземпляр API с тем же профилем Chromium. Не открывайте вручную директорию `data/browser-profile` в другом Chromium во время сбора.

## Что подтверждено и что ограничено

При исследовании 20.09.2026 обычный HTTP-запрос каталога Циана вернул **HTTP 200 со страницей «Вы не робот?»**. В локальном журнале есть запуск, сохранивший две реальные карточки Циана до отмены. Полный сбор по новым параметрам поиска через капчу не подтвержден. Парсер и UI проверены на синтетических HTML-фикстурах и в браузерных тестах. Playwright выполняет JavaScript, но **не гарантирует** отсутствие блокировок и не обходит защиту. Подробности и первоисточники: [docs/cian-research.md](docs/cian-research.md).

Селекторы площадок могут изменяться. Адаптер читает DOM (`data-name`, `data-mark`) и JSON-LD, без выполнения скриптов из сохраненного HTML и без обращения к недокументированному поисковому API. Не распознанные страницы возвращают ошибку. Сбор запускается пользователем; фонового расписания нет.

Дедупликация выполняется **по канонической ссылке**, а не по адресу/фото между площадками. Контакты продавцов не собираются. Фото сохраняются как URL и загружаются браузером с площадки: офлайн-копий нет, ссылки могут истечь. XLSX содержит ссылки на фото, а не встроенные изображения.

## Расчеты

Для срока `N` месяцев:

```text
Комиссия = аренда × процент / 100 (либо фиксированная сумма)
В месяц = аренда + коммунальные платежи
На въезд = в месяц + залог + комиссия + прочие разовые расходы
Расходы за срок = в месяц × N + комиссия + прочие разовые расходы
Денежные выплаты за срок = расходы за срок + залог
В среднем за месяц = расходы за срок / N
```

Предполагаются постоянная ставка, оплата первого месяца при въезде и полностью возвратный залог. Рассрочка залога, предоплата нескольких месяцев, повышение аренды и удержания из залога не моделируются. Пустые коммунальные/залог/комиссия — **неизвестно**, 0 — **платежа нет**. Итог с неизвестными значениями является нижней оценкой. В XLSX неизвестные значения остаются пустыми; формулы и отметка неполных условий позволяют уточнить расчет в Excel.

## Данные и API

По умолчанию `data/rent.sqlite` и `data/browser-profile/` находятся в корне репозитория и исключены из Git. Профиль может содержать cookies площадок. Для резервной копии остановите приложение и скопируйте папку `data`.

- `DATA_DIR` — каталог данных (абсолютный путь рекомендуется).
- `DATABASE_PATH` — отдельный путь к SQLite, полезен для тестов.
- `PORT` — порт API (по умолчанию 3001). В dev прокси Vite настроен на 3001.

API привязан к `127.0.0.1`. Авторизации пользователей нет: это приложение для одного пользователя на локальном компьютере. Изменяющие запросы принимаются как JSON с проверкой Origin. Не публикуйте API напрямую в интернет без добавления авторизации.

| Метод          | Маршрут                            | Назначение                   |
| -------------- | ---------------------------------- | ---------------------------- |
| GET            | `/api/listings`                    | Все квартиры                 |
| POST           | `/api/listings`                    | Добавление                   |
| PATCH / DELETE | `/api/listings/:id`                | Изменение / удаление         |
| POST           | `/api/imports/browser`             | `{url, limit: 10, pages: 1}` |
| POST           | `/api/imports/html`                | `{url, html}`                |
| GET            | `/api/imports`                     | Последние запуски            |
| POST           | `/api/imports/:id/cancel`          | Отмена                       |
| GET            | `/api/export.xlsx?ids=…&months=12` | XLSX, IDs через запятую      |
| POST / DELETE  | `/api/demo`                        | Добавить / убрать демо       |

## Разработка и проверки

```sh
npm test             # unit + API integration; отдельная временная SQLite
npm run test:e2e     # production UI + API, отдельная база и порт 3100
npm run format:check
npm run build
```

E2E проверяет пустое состояние, демо, фильтры, избранное, расчет, заметки, сравнение, скачивание XLSX, ручное добавление, HTML-импорт и отсутствие горизонтального скролла на телефоне. Скриншоты — `test-results/`. E2E не использует живой Циан и не требует решения капчи.

```text
apps/api/src/        NestJS, SQLite, Playwright, парсеры и XLSX
apps/web/src/        React-интерфейс
packages/shared/    Схемы Zod, типы, общий расчет расходов
tests/              Фикстуры, unit, API integration и UI E2E
docs/               Исследование способов сбора
```

Внешние зависимости интерфейса: Google Fonts (есть системный fallback), источники фотографий. База и основные функции работают локально.

Фоновый режим: браузер запускается без окна. При капче задача показывает кнопку «Открыть окно проверки»; только по нажатию фоновый браузер закрывается и открывается видимый с тем же локальным профилем и текущим URL. После проверки продолжается тот же запуск с сохраненными счетчиками и результатами. Окно остается видимым до завершения этого запуска; следующий сбор снова начинается в фоне. На запрос открытия и ручную проверку отводится по 3 минуты.

### Личная оценка и актуализация

На каждой карточке — пять оценок от зеленой 5 («Отличный вариант») до красной 1 («Не подходит»). Оценка сохраняется локально, сбрасывается крестиком и доступна в сортировке «По моей оценке»; неоцененные квартиры идут после оцененных. XLSX включает числовую колонку «Моя оценка / 5».

«Актуализировать» повторно открывает исходное объявление в фоновом браузере и обновляет его условия и фотографии. Оценка, заметки, избранное и прочие пользовательские расходы сохраняются. При капче доступно окно проверки. Одновременно выполняется один сбор; у демо и ручных карточек без подтвержденного источника кнопка недоступна. Ошибка чтения не удаляет карточку и не отмечается успешным обновлением.
