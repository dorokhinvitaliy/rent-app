# Гостевой сайт и личные аккаунты

Объявления — общие. Без входа доступны поиск по базе, просмотр, расчёты, сравнение, экспорт публичных данных и запуск поиска свежих объявлений на Циане. Единая форма сначала фильтрует базу. Если совпадений меньше 10, автоматически запускается поиск на Циане; повторный идентичный запрос использует текущую задачу или результат последних 60 секунд. Кнопка «Ещё загрузить с Циана» внизу списка запускает дополнительный сбор; сохранённые URL не дублируются. Авито пока не подключено.

Комментарии, избранное, оценки (включая личный архив), рейтинг и подборки хранятся отдельно для каждого пользователя. API возвращает только его отметки; гостям — пустые значения. Запуски парсера тоже принадлежат инициатору. Одновременно выполняются два сбора с отдельными профилями Chromium (PARSER_CONCURRENCY, 1–3). Остальные задачи ждут FIFO: максимум 20 задач всего, 3 на пользователя. Чужой запуск нельзя отменить. Прогресс отображается компактными уведомлениями; технический журнал остаётся в разделе импорта. Общую информацию и удаление объявления может менять только владелец. Ручное добавление, HTML-импорт и редактирование общих данных доступны только администратору (первому пользователю). Остальные пользователи могут запускать парсинг и актуализацию, а также менять свои комментарии, оценки и избранное.

Регистрация открытая: имя, email и пароль, без кода приглашения. Все новые аккаунты после владельца получают роль `member`. Первый зарегистрированный аккаунт становится владельцем и атомарно получает старые личные отметки и подборки. До регистрации эти отметки недоступны гостям. Исходные JSON очищаются от личных полей после переноса. Согласованная резервная копия реальной локальной базы до переноса личных отметок находится в `data/backups/`.

В существующей установке каталог данных по умолчанию — `../data` относительно репозитория; на сервере Compose явно задаёт `/data`. Пароли хранятся как scrypt с индивидуальной солью. Сессии — случайные токены, в SQLite только хеши, в браузере HttpOnly/SameSite cookie; в production также Secure. Срок сессии 30 дней, выход отзывает токен. Почтовое восстановление пароля пока не подключено; подтверждение email также пока не требуется.

# Развёртывание

Один Linux-сервер с Docker Compose. Стартовая конфигурация: 2 vCPU, 4 ГБ RAM, 40 ГБ сетевого SSD. SQLite и профиль Chromium находятся в постоянном Docker volume `rent-data`. Горизонтальное масштабирование приложения с SQLite и текущим парсером не поддерживается.

1. Скопировать `.env.example` в `.env`, задать `DOMAIN`.
2. DNS имени должен указывать на публичный IP сервера. Разрешить входящие 80/443, SSH 22 только с адреса администратора. Порт API 3001 и VNC не открывать в интернет.
3. `docker compose up -d --build`. Caddy выпускает и обновляет сертификат HTTPS. Указать `APP_ORIGIN` автоматически помогает Compose.
4. На новой пустой установке первым зарегистрировать владельца. На действующем сайте владелец уже создан; последующие регистрации не дают прав администратора.

## Миграция локальных данных

Остановить приложение на время восстановления. Переносить согласованную SQLite-копию, сделанную через SQLite backup API или `.backup`; не копировать только `rent.sqlite` во время работы WAL. В volume поместить копию под именем `/data/rent.sqlite`, владелец UID/GID 1000. Если локальный владелец ещё не зарегистрирован, зарегистрировать его первым на сервере после переноса. Если зарегистрирован — переносится его аккаунт и хеш пароля вместе с базой. Не переносить чужие сессии браузера площадки без необходимости.

## Браузер на Linux

Chromium запускается с реальным окном на виртуальном экране Xvfb, не в headless. Это не гарантирует доступ с облачного IP: Циан может вернуть 403 или капчу. Для ручной проверки есть опциональный VNC:

- Создать пароль интерактивно: `docker compose exec app x11vnc -storepasswd /data/vnc-password`.
- Установить `ENABLE_VNC=1`, пересоздать app.
- Со своего компьютера: `ssh -L 5901:127.0.0.1:5900 yc-user@SERVER_IP`, затем VNC-клиент на `127.0.0.1:5901`.
- После проверки вернуть `ENABLE_VNC=0`.

Пароль VNC и private SSH key не коммитить. VNC привязан только к loopback хоста. Проверку в браузере выполняет владелец сервера; пользователь сайта видит состояние задания.

## Резервирование и обновления

Перед обновлением выполнить согласованный backup SQLite. Хранить несколько копий, дополнительно настроить снимки сетевого диска в Yandex Cloud; копия на том же диске не защищает от его удаления. Проверять восстановление копии на отдельной базе.

Обновление: `docker compose build app && docker compose up -d app`. Проверка: `docker compose ps`, `docker compose logs --tail=100 app`, HTTPS `/api/health`. Не выполнять `docker compose down -v`: это удалит данные и сертификаты.

Проверено после запуска: HTTP → HTTPS, валидный сертификат Let's Encrypt, health API, 100 квартир в гостевой выдаче без личных отметок, окно входа при лайке. ## Автодеплой через GitHub Actions

Workflow `.github/workflows/deploy.yml` запускается при push в `main` или вручную через Actions → Test and deploy → Run workflow. Сначала GitHub-hosted runner выполняет `npm test` и браузерные тесты. Только после успеха начинается деплой. Изменения в других ветках не публикуются. Одновременно идёт не более одного workflow production; устаревший SHA пропускается сервером.

Окружение GitHub `production` разрешает только ветку `main`. Единственный серверный runner `rent-production` работает отдельным пользователем `rent-runner`, без членства в группе Docker. В workflow ему не передаются SSH-ключи или облачные токены. Sudo разрешает только установленный root-owned `/usr/local/sbin/rent-deploy`. Этот скрипт принимает SHA, сам получает текущий `main` фиксированного репозитория `dorokhinvitaliy/rent-app` и сверяет ревизию. На серверном runner нет checkout/action стороннего кода. Не добавлять на него jobs для pull_request/pull_request_target или веток участников: публичные PR проверяются только на GitHub-hosted runners.

Скрипт-источник: `deploy/github-deploy.sh`. Изменения самого root-entrypoint устанавливаются администратором отдельно, а не workflow. Размещение:

- `/opt/actions-runner` — служба runner, автоматически стартует после перезагрузки;
- `/opt/rent-repository.git` — root-owned git cache публичного репозитория;
- `/opt/rent-releases/<SHA>` — релизы с отдельными Docker image tags;
- `/opt/rent-app` — ссылка на текущий успешный релиз;
- `/opt/rent-deployed-sha` — текущая опубликованная ревизия;
- `/etc/rent-app.env` — постоянный DOMAIN и настройки VNC; без invite-кода.

Новый образ собирается до остановки старого. Перед переключением создаётся согласованная копия SQLite. Compose ждёт healthy, затем проверяется публичный HTTPS health endpoint. При ошибке запуска/health возвращается прежний image и Compose; база не откатывается автоматически, чтобы не потерять новые данные пользователей. Будущие миграции БД должны сохранять обратную совместимость. После успеха сохраняются текущий и два недавних релиза (плюс bootstrap), ограничивается кеш сборки. Короткая пауза при пересоздании контейнера возможна: это один сервер без балансировщика.

Ручной повтор: Run workflow для `main`. Диагностика: GitHub Actions logs; на сервере `sudo docker compose -p rent-app -f /opt/rent-app/compose.yaml ps` и `sudo systemctl status 'actions.runner.*'`. Для ручного отката использовать Compose сохранённого релиза с тем же project name `rent-app`, затем переключить `/opt/rent-app`; не удалять volumes.

## Обновление расширенных данных

`POST /api/imports/refresh-all` доступен только администратору. Ставит все реальные объявления Циана в две задачи существующей очереди с отдельными браузерными профилями и паузами между страницами. Повторный вызов во время работы возвращает текущие задачи. Личные оценки, заметки, подборки и просмотры сохраняются. 403 или капча могут прервать обновление; успешное завершение проверять по `scanned`, `updated`, `warnings` и `details.checkedAt`, а не только статусу задачи.

Таблица `viewings` добавляется при запуске без изменения существующих данных. PDF использует установленный Chromium в отдельном временном контексте; разрешены только изображения известных CDN, запросы к произвольным адресам блокируются.
