# Гостевой сайт и личные аккаунты

Объявления — общие. Без входа доступны поиск по базе, просмотр, расчёты, сравнение, экспорт публичных данных и запуск поиска свежих объявлений на Циане. Кнопка «Найти квартиры» не обращается к площадке. «Найти свежие объявления» явно запускает сбор; сохранённые URL не дублируются. Авито пока не подключено.

Комментарии, избранное, оценки (включая личный архив), рейтинг и подборки хранятся отдельно для каждого пользователя. API возвращает только его отметки; гостям — пустые значения. Запуски парсера тоже принадлежат инициатору. Одновременно выполняется один сбор, чужой запуск нельзя отменить. Общую информацию и удаление объявления может менять только владелец. Обычные пользователи могут добавлять квартиры и запускать актуализацию.

Регистрация закрытая, по `AUTH_INVITE_CODE`. Первый зарегистрированный аккаунт становится владельцем и атомарно получает старые личные отметки и подборки. До регистрации эти отметки недоступны гостям. Исходные JSON очищаются от личных полей после переноса. Согласованная резервная копия реальной локальной базы до переноса личных отметок находится в `data/backups/`.

Локально код автоматически создаётся в `<DATA_DIR>/invite-code` (права 0600). В существующей установке каталог данных по умолчанию — `../data` относительно репозитория; на сервере Compose явно задаёт `/data`. На сервере задайте случайный код в `.env`. Пароли хранятся как scrypt с индивидуальной солью. Сессии — случайные токены, в SQLite только хеши, в браузере HttpOnly/SameSite cookie; в production также Secure. Срок сессии 30 дней, выход отзывает токен. Почтовое восстановление пароля пока не подключено; это закрытая первая версия, не публичная регистрация.

# Развёртывание

Один Linux-сервер с Docker Compose. Стартовая конфигурация: 2 vCPU, 4 ГБ RAM, 40 ГБ сетевого SSD. SQLite и профиль Chromium находятся в постоянном Docker volume `rent-data`. Горизонтальное масштабирование приложения с SQLite и текущим парсером не поддерживается.

1. Скопировать `.env.example` в `.env`, задать `DOMAIN` и `AUTH_INVITE_CODE` (`openssl rand -hex 32`). Код хранить отдельно от git.
2. DNS имени должен указывать на публичный IP сервера. Разрешить входящие 80/443, SSH 22 только с адреса администратора. Порт API 3001 и VNC не открывать в интернет.
3. `docker compose up -d --build`. Caddy выпускает и обновляет сертификат HTTPS. Указать `APP_ORIGIN` автоматически помогает Compose.
4. Открыть сайт, зарегистрировать владельца с кодом приглашения. Остальным участникам передать этот код отдельно. Не размещать код в публичной документации сайта.

## Миграция локальных данных

Остановить приложение на время восстановления. Переносить согласованную SQLite-копию, сделанную через SQLite backup API или `.backup`; не копировать только `rent.sqlite` во время работы WAL. В volume поместить копию под именем `/data/rent.sqlite`, владелец UID/GID 1000. Если локальный владелец ещё не зарегистрирован, зарегистрировать его первым на сервере после переноса. Если зарегистрирован — переносится его аккаунт и хеш пароля вместе с базой. Не переносить чужие сессии браузера площадки без необходимости.

## Браузер на Linux

Chromium запускается с реальным окном на виртуальном экране Xvfb, не в headless. Это не гарантирует доступ с облачного IP: Циан может вернуть 403 или капчу. Для ручной проверки есть опциональный VNC:

- Создать пароль интерактивно: `docker compose exec app x11vnc -storepasswd /data/vnc-password`.
- Установить `ENABLE_VNC=1`, пересоздать app.
- Со своего компьютера: `ssh -L 5901:127.0.0.1:5900 rent@SERVER_IP`, затем VNC-клиент на `127.0.0.1:5901`.
- После проверки вернуть `ENABLE_VNC=0`.

Пароль VNC и private SSH key не коммитить. VNC привязан только к loopback хоста. Проверку в браузере выполняет владелец сервера; пользователь сайта видит состояние задания.

## Резервирование и обновления

Перед обновлением выполнить согласованный backup SQLite. Хранить несколько копий, дополнительно настроить снимки сетевого диска в Yandex Cloud; копия на том же диске не защищает от его удаления. Проверять восстановление копии на отдельной базе.

Обновление: `docker compose build app && docker compose up -d app`. Проверка: `docker compose ps`, `docker compose logs --tail=100 app`, HTTPS `/api/health`. Не выполнять `docker compose down -v`: это удалит данные и сертификаты.
