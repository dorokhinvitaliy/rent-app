# Получение объявлений Циана: исследование и реализация

Дата проверки: **20 сентября 2026**.

## Краткий результат

Для личного локального приложения выбран **Playwright + видимый Chromium + сохраненный профиль**. Selenium также подходит для запуска JavaScript и чтения DOM, но Playwright удобно интегрируется с TypeScript/NestJS и дает навигацию, таймауты и управление контекстом в одном SDK. Используется отдельный профиль, а не обычный профиль пользователя.

Это браузерный импорт по запросу пользователя, а не гарантированно работающий круглосуточный краулер. В локальном журнале обнаружен запуск от 20.09.2026 12:18 UTC, сохранивший две карточки Циана до отмены. Это подтверждает отдельный успешный импорт, но не прохождение капчи или полный поиск по новым параметрам.

## Официальный API

[Официальная страница Циан API](https://promo.cian.site/api) описывает интеграцию с личным кабинетом профессионального участника: статистика своих объявлений, баланс, сообщения и сотрудники. В опубликованном описании не найден общедоступный метод поиска всех чужих объявлений об аренде. Это вывод по изученным публичным материалам, а не утверждение об отсутствии любых коммерческих продуктов данных.

[Статья о получении API-ключа](https://www.cian.ru/novosti-teper-dostup-k-tsian-api-mozhno-poluchit-prjamo-v-lichnom-kabinete-329732/) также описывает доступ профессионалов к личному кабинету. XML-выгрузка означает размещение собственных объявлений на Циан; это не обратный фид каталога.

Если нужен коммерческий масштаб и договорные гарантии, следующий шаг — согласовать доступ к данным с Цианом. В приложении ключ или подписка не требуются.

## Фактически проверенный HTTP

Запрос из текущего окружения:

```sh
curl -L 'https://www.cian.ru/cat.php?deal_type=rent&engine_version=2&offer_type=flat&region=1&type=4'
```

Результат: HTTP 200, около 11,8 КБ HTML, `<title>Вы не робот?</title>`, SmartCaptcha. Поэтому проверка только HTTP-статуса неверна: это не успешная выдача каталога. Запрос robots.txt через инструмент веб-поиска вернул 403; актуальное содержимое robots.txt не удалось подтвердить.

## Подходы

| Подход                           | Результат исследования                               | Решение                                 |
| -------------------------------- | ---------------------------------------------------- | --------------------------------------- |
| Официальный API личного кабинета | Подтверждены управление своим аккаунтом и статистика | Не используется как поиск чужих квартир |
| Обычный fetch/HTTP + HTML        | В окружении получена капча с HTTP 200                | Не выбран основным способом             |
| Playwright / Selenium            | Выполняют JS; браузерная сессия сохраняется          | Playwright в видимом режиме             |
| Внутренние JSON-эндпоинты сайта  | Публичного стабильного контракта не подтверждено     | Не используются                         |
| Сторонние платные API            | Требуют проверки актуальности, договора и расходов   | Не подключены                           |
| Сохраненный HTML / ручной ввод   | Не требуют автоматического доступа к сайту           | Реализованы как запасной путь           |

[Документация Playwright о постоянном контексте](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-persistent-context) подтверждает сохранение сессии в пользовательском каталоге. [Установка браузеров](https://playwright.dev/docs/browsers) выполняется командой `npx playwright install chromium`.

В открытом исходном коде [cianparser](https://github.com/lenarsaitov/cianparser) и его [парсере списка](https://github.com/lenarsaitov/cianparser/blob/main/cianparser/flat/list.py) использованы DOM-карточки `article[data-name="CardComponent"]` и ссылки внутри `LinkArea`. Это подтверждает применимость DOM-подхода в предыдущих версиях сайта, но не доказывает актуальность каждого селектора сейчас. Python-библиотека в проект не включена; TypeScript-адаптер написан отдельно.

## Конвейер в приложении

1. Проверить HTTPS URL и домен Циана/Яндекс Недвижимости, исключить продажу и каталог посуточной аренды Циана.
2. Создать задачу в SQLite и открыть отдельный Chromium с локальным профилем.
3. При распознанной капче показать статус «Ожидает проверки», ждать ручного решения до трех минут. Без прокси-ротации, маскировки fingerprint и автоматического решения капчи.
4. Из каталога получить ссылки на квартиры. Открывать карточки последовательно с паузой 2 секунды, чтобы получить расходы и фотографии. Максимум 30 объектов и 3 страницы за запуск.
5. Для Циана сначала читать JSON-состояние конкретного объявления из `frontend-offer-card → defaultState → offerData.offer`, проверяя ID из ссылки, месячный период и валюту. Сверять цену с основным `PriceInfo`. Комиссия арендатора — `clientFee`, не `agentFee`; маршрут пешком — только `travelType=walk`. Исключенные счетчики оставляют коммунальные расходы неизвестными. При отсутствии состояния использовать DOM/JSON-LD; не искать цену и признак посуточной аренды по тексту всей страницы.
6. Нормализовать и проверить данные Zod. Записать SQLite по уникальной ссылке; сохранить пользовательские заметки, избранное, прочие расходы. Межплощадочное совпадение объектов автоматически не определяется.
7. Показать результат, предупреждения или ошибку в истории. Успешно полученные записи сохраняются при частичном сбое.

Парсинг состояния и JSON-LD использует `JSON.parse`, не `eval`. Сохраненные скрипты не выполняются. Browser URL ограничен источниками, переходы к локальным IP блокируются на уровне сетевых маршрутов. Это не предназначенный для произвольных сайтов сервис загрузки URL.

## Ограничения и развитие

- CAPTCHA, изменение DOM и авторизация могут остановить сбор. Нужна проверка на актуальных страницах с доступной пользователю сессией.
- Яндекс Недвижимость — экспериментальный DOM/JSON-LD адаптер; надежность на живом каталоге не подтверждена.
- Нет автоматического отслеживания снятия объявления, фонового расписания, истории цен и дедупликации между площадками.
- Фото хранятся как URL; для полной офлайн-работы нужен отдельный ограниченный кеш изображений.
- Тексты комиссий могут иметь новые форматы. Неоднозначные или неизвестные суммы следует проверить в редакторе.
- Большая коллекция потребует серверной пагинации/фильтров вместо получения всего локального списка.
- Для командного или публичного развертывания нужны авторизация и изоляция профилей браузера.

## Валидация

Unit/API тесты используют синтетические HTML-страницы и минимальные финансовые/транспортные поля трех реальных объявлений, проверенных 20.09.2026. Проверены месячные цены 82 500, 29 900 и 80 000 ₽, залоги, комиссия, исключенные счетчики и пешее метро. Регрессионные тесты добавляют постороннюю цену и рекламу посуточной аренды, проверяют конфликт цены и несовпадение ID. Они проверяют нормализацию, расчеты, данные SQLite, блокировки URL, признаки капчи и XLSX. UI E2E проверяет взаимодействия в Chromium. Они не являются доказательством стабильного доступа к живому каталогу Циана.

## Поиск из формы приложения

Параметры передаются серверу, где строится адрес каталога. Регион, комнаты, бюджет и пешая доступность используют схему URL из [исходного URLBuilder cianparser](https://github.com/lenarsaitov/cianparser/blob/main/cianparser/url_builder.py) и его [констант](https://github.com/lenarsaitov/cianparser/blob/main/cianparser/constants.py): `region`, `room1`–`room5`, `room9` (студия), `minprice`, `maxprice`, `only_foot=2`, `foot_min`. Для площади применяются `mintarea`/`maxtarea`, для этажа — `minfloor`. Это параметры веб-сайта, не документированный стабильный API; их действие на текущей живой выдаче не подтверждено.

Поэтому ограничения цены, площади, комнат, этажа и пешего времени повторно применяются к каждой разобранной карточке. При обязательном, но неизвестном поле совпадение не сохраняется. «Без комиссии» проверяется по явно распознанному нулю, а не по принадлежности объявления собственнику. Задача хранит исходные критерии, счетчики и ID сохраненных совпадений. Автотест конвейера использует подмененный браузер, UI-тест нового сценария — подмененный ответ запуска; они не обращаются к живому Циану.

Локальные записи успешного импорта: объявления `332764226` и `334029938`, `demo=false`, сохранены браузерной задачей со счетчиком `count=2`. Текущая доступность исходных объявлений отдельно не проверялась.

## Выбор станций метро

Форма поддерживает несколько станций (логика «любая из выбранных») и передает их ID в `metro[0]`, `metro[1]` и т. д. вместе с `foot_min` и `only_foot`. Названия и ID локального справочника сняты 20.09.2026 с карты фильтров Циана для регионов 1, 2 и 4777. Для Москвы источник — [JSON карты Циана v14](https://static.cdn-cian.ru/frontend/collections-assets/metro/v14.0.0/1.json); для Петербурга и Казани — данные компонентов карты в соответствующей выдаче Циана. Полные страницы, конфигурации и данные сессии в репозиторий не включены. Московские станции, отмеченные в фильтре Циана как строящиеся, исключены. Справочник является снимком карты площадки, не гарантией полноты или актуальности транспортной сети; обновлять его нужно при изменении карты Циана.

Одноименные станции в городе объединены в один пункт со всеми известными ID. При смене города выбор сбрасывается. Сервер проверяет принадлежность ID городу. Парсер сохраняет все явно указанные пешие маршруты; время сравнивается именно у выбранной станции. В карточке результата показывается ближайшая из подходящих выбранных станций. Маршруты на транспорте не проходят этот фильтр, неизвестное время не считается подходящим. Старые записи SQLite совместимы: поле маршрутов добавляется при новом импорте. Для DOM-адаптера без ID применяется точное нормализованное название станции, а не поиск подстроки.
